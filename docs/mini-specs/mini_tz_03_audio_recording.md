# Мини-ТЗ 03: Запись лекции

## Цель
Реализовать запись аудио лекции с управлением сессией записи, сохранением локального файла и сохранением транскрибации для последующего отображения в интерфейсе.

## Scope
- `Record/Pause/Resume/Stop`.
- Таймер записи и индикация состояния.
- Контроль лимита длительности по плану подписки.
- Сохранение файла в формате `m4a`.
- Сохранение результата транскрибации, связанного с записью.
- Отображение транскрибации на экране записи.

## Технические параметры
- Формат: AAC / m4a.
- Частота: 44.1 kHz.
- Каналы: mono.
- Битрейт: 32–64 kbps.

## Модель данных записи
- Для записи и последующей обработки используется существующая модель `Lecture`.
- Минимально необходимые поля для сценария записи: `id`, `createdAt`, `duration`, `status`, `transcript`, а также ссылка на локальный или загруженный аудиофайл.
- `transcript` хранит последнюю сохраненную текстовую версию транскрибации для текущей лекции.
- Источник истины для экрана записи: `RecorderViewModel`, который читает и обновляет текущую `Lecture` через repository/store слой.

## Жизненный цикл транскрибации
- При старте записи создается или инициализируется `Lecture` в статусе `draft`.
- После upload/STT-обработки backend обновляет `Lecture.transcript`.
- Каждое новое обновление транскрибации должно сохраняться в `Lecture.transcript`.
- При повторном открытии экрана записи пользователь должен видеть последнюю сохраненную транскрибацию, привязанную к этой `Lecture`.

## Требования к UI экрана записи
- На экране записи должен быть блок транскрибации под контролами записи или в отдельной секции этого же экрана.
- UI должен показывать последнее сохраненное состояние `transcript`, а не только временный текст в памяти.
- Если транскрибация еще не готова, экран показывает статус-заглушку, например `Транскрибация появится после обработки`.
- При поступлении новых фрагментов транскрибации текст должен обновляться без ручного перезахода на экран.
- Длинная транскрибация должна поддерживать вертикальный скролл и копирование текста.

## Артефакты
- `RecordingManager`.
- `RecorderViewModel`.
- Экран `Recorder`.
- Расширение repository/store слоя для обновления `Lecture.transcript` и статуса записи.

## Критерии приемки
- Все команды записи работают стабильно.
- Таймер не расходится с фактической длительностью.
- Полученный файл воспроизводится и доступен для upload.
- Транскрибация сохраняется вместе с записью и доступна после перезапуска экрана.
- На экране записи пользователь видит актуальный текст транскрибации для текущей записи.
